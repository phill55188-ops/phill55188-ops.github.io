# SignalBrief Follow-up Implementation Plan

> For agentic workers: use superpowers execution and verification procedures. Cameron authorized implementation, delegation, deployment and finalization.

**Goal:** Research questions about individual analysis sections in a branded evidence-enabled dialog.
**Architecture:** Existing vanilla app captures immutable analysis context, a dedicated UI module manages per-section sessions, and the existing authenticated Cloudflare Worker performs OpenAI web research.
**Tech Stack:** HTML/CSS/JavaScript, Cloudflare Worker, OpenAI Responses API.
**Spec:** ../specs/2026-11-16-followup-design.md

## Global constraints
Preserve current analysis endpoint, authentication, source labels, typography and unrelated files. Never publish secrets. Evidence is optional, three files up to4MiB each. Cap response viewport480px.

## Review focus
- Context must use the analyzed source rather than subsequent input edits.
- Each section's drafts/history must remain separate.
- Closing/canceling cannot display a stale answer in another section.
- Unsupported/oversized attachments must be removable without blocking question-only use.
- API failures and offline behavior must leave retry usable.

## Tasks
- [x] Backend worker: server-owned research instructions, validated bounded payload/evidence, real web tool/citations, auth/error/incomplete handling; run mocked upstream tests.
- [x] Frontend: followup.js and followup.css; integrate completed-card buttons, immutable run context, service-worker cache bump; test state transitions and inspect rendering.
- [x] Two independent reviewers with no prior product knowledge test additions, report severity/evidence and retest corrections.
- [ ] Deploy atomic source commit through existing GitHub/Cloudflare build; verify actual public version, authenticated research both without/with evidence and visible live dialog.
- [ ] Save release/report/records to project Drive; independently verify tracker/canon promotion and predecessor preservation.
